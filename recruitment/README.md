# מערכת גיוס שגרירים — ערב שותפות, בית ספר חב"ד עפולה

אתר קליל למכשירים ניידים לניהול "ערב שותפות": רשימת אנשי קשר, שגרירים שאחראים על קבוצת אנשים, ומעקב סטטוסים לכל אחד. Node.js (Express) + PostgreSQL, מוכן לפריסה ב-Railway.

## מה יש במערכת

- **אין מסך התחברות לשגריר רגיל.** בכניסה לאתר בוחרים "מי אתה?" מרשימת השגרירים — הבחירה נשמרת במכשיר. כל שגריר יכול לראות את כל שאר השגרירים ברשימה, ולהתחלף ולפעול בשם כל שגריר אחר (כפתור "🔄 החלף זהות"). **רק בחירת זהות מנהל דורשת קוד גישה** (ראו סעיף "מי הוא מנהל" למטה).
- 6 לשוניות רשימה: **שלי**, **פתוחים** (לא משויכים — עם "קח לרשימה שלי"), **הכל** (הרשימה המלאה, פתוחה לכולם — גם כאן יש "קח לרשימה שלי" לכל איש קשר שעדיין לא משויך), **מועמדים** (למועמדים לשגרירות), **סטטיסטיקה** (לוח מובילים וגרפים — ראו למטה), ו**הוספה**. לכל שגריר שמשויך לאיש קשר יש גם קישור "**ביטול שיוך**" בכרטיס הפרטים, שמחזיר אותו ל"לא משויכים".
- בכל לשונית רשימה: **חיפוש** (שם/טלפון), **מיון** (ברירת מחדל: לפי א'-ב', וגם לפי תאריך/סטטוס), סינון לפי קטגוריה וסטטוס, תיבת "להציג רק ללא סיווג", ו**בחירה מרובה** (סימון כמה אנשי קשר ביחד — סיווג מרוכז דרך רשימת סימון של הקטגוריות הקיימות, מחיקה מרוכזת עם אישור, ובלשוניות "שלי"/"פתוחים"/"הכל" גם **עדכון סטטוס מרוכז**, ובלשוניות "פתוחים"/"הכל" גם "קח לרשימה שלי" מרוכז לכל הנבחרים הפנויים בבת אחת). שורת הפעולות המרוכזות נשארת **דביקה בראש המסך** בזמן גלילה כל עוד יש בחירה, ומתאפסת אוטומטית מיד אחרי החלת פעולה.
- **🎟️ הזמנה אישית לאירוע (כרגע פתוח למנהל בלבד, לבדיקה)**: לכל איש קשר יש קישור אישי (`/invite/<טוקן>`) שאפשר לשלוח לו, ומראה לו עמוד הזמנה נפרד ומעוצב עם השם שלו ואפשרות לאישור הגעה (מגיע/ה, לא יכול/ה להגיע אבל רוצה לתרום, או לא יכול/ה להגיע) — כולל שאלה אם מגיע/ה לבד או עם בן/בת זוג. מכרטיס הפרטים אפשר להגדיר **שם האיש בהזמנה** ו**שם האישה בהזמנה** (שני השמות מוצגים על ההזמנה זה מתחת לזה **באותו גודל**, האיש ראשון והאישה שנייה) שיופיעו במקום/בנוסף לשם הרגיל שברשימה, **מקום ישיבה** נפרד למוזמן/ת ולבן/בת הזוג, וגם **עדכון ידני של "מגיע/ה לבד / עם בן-בת זוג / לא ידוע"** — כך שאפשר לסמן את זה תמיד גם ללא תלות באישור הגעה עצמי של האורח/ת (שממשיך לעדכן את אותו שדה אם וכאשר האורח/ת עצמו/ה מאשר/ת). אישור ההגעה של האורח/ת מעדכן את אותו שדה סטטוס שהשגרירים רואים (מתועד בהיסטוריה כ"אישור עצמי של המוזמן/ת").
- **עדכון סטטוס נמצא בראש כרטיס הפרטים** (מיד אחרי השם) לגישה מהירה — ולחיצה נוספת על הסטטוס שכבר מסומן מבטלת את הסימון וחוזרת ל"טרם נקבע סטטוס" (ההיסטוריה נשארת מתועדת). **עדכון סטטוס (בודד או מרוכז) על איש קשר שעדיין לא משויך לאף שגריר משייך אותו אוטומטית אליכם** — כך שברגע שמתחילים לטפל במישהו הוא כבר נמצא ב"שלי".
- כל שגריר יכול **להוסיף אנשי קשר חדשים**, **לערוך** כל איש קשר (שם/טלפון/הערות) ו**למחוק** אנשי קשר לא רלוונטיים — פתוח לכולם כחלק מתחזוקת הרשימה המשותפת.
- **סיווג מרובה וחופשי, עם צבע קבוע לכל סיווג**: לכל איש קשר אפשר לצרף כמה סיווגים, ולהוסיף/להסיר בכל רגע — פתוח לכולם. כל שם סיווג מקבל אוטומטית צבע קבוע משלו (מתוך פלטת 10 צבעים), כך שאותו סיווג נראה תמיד באותו צבע בכל מסך.
- **שיח פנימי לכל איש קשר** ("💬 מי מכיר את זה?"): כפתור ℹ️ בפינת כל כרטיס (עם מספר ההודעות אם יש) פותח דיון קטן — כל שגריר יכול לכתוב הודעה (למשל "מישהו מכיר? מאיפה?") ולמחוק הודעה שכתב בעצמו; מנהל יכול למחוק כל הודעה.
- **5 סטטוסים קבועים** עם **היסטוריה מלאה** (ראשוני/קודם/נוכחי, עם תאריך עברי מלא באותיות (למשל "יח באלול תשפ״ו") לצד הלועזי בכל תיעוד).
- **סינון לפי שגריר בלשונית "הכל" (למנהל)**: רשימה נפתחת עם כל השגריר ומספר האנשים שלקח ליד השם (וגם אפשרות "ללא שיוך"), לסינון מהיר של הרשימה המלאה.
- **מועמדים לשגרירות**: לסמן מישהו כמתאים להיות שגריר, עם **"אני לוקח אחריות"** או **"לשאול שגרירים אחרים"** (משאיר פתוח לכל מי שירצה לקחת) — כולל אפשרות לוותר על האחריות בחזרה.
- **"זה אני"**: כל שגריר יכול לסמן איש קשר אחד בלבד ברשימה כמייצג אותו עצמו (למשל אם הופיע ברשימה המקורית לפני שהצטרף כשגריר) — סימון על איש קשר חדש מסיר אוטומטית את הסימון מהקודם, והוא לא נספר בסטטיסטיקה שלו כ"אדם שגייס".
- **שינוי שם שגריר** ו**מחיקת שגריר** מתוך "ניהול" (למנהל בלבד).
- **סטטיסטיקה ולוח מובילים** (פתוח לכולם, לעידוד): כמה אנשים לכל שגריר ובאיזה סטטוס, גרף "מי הביא הכי הרבה אנשים למגיע לאירוע", גרף "מי הכי משקיע" (לפי מספר עדכוני סטטוס), וציר זמן שמראה את קצב ההתקדמות המצטבר של כולם — לצד משפטי עידוד מתחלפים ופרגון לשגריר/ה המוביל/ה.
- **מסך ניהול למנהל בלבד**: הוספה/עריכה/מחיקה של שגרירים, ניהול קטגוריות, ו**ייבוא מרוכז** — הדבקת עשרות/מאות שורות בבת אחת מאקסל/Google Sheets.

## מי הוא "מנהל"?

בהרצה הראשונה (כשעדיין אין אף שגריר במסד הנתונים) המערכת יוצרת אוטומטית שגריר-מנהל אחד, לפי משתני הסביבה:

```
ADMIN_NAME=מנהל     # השם שיופיע ברשימת "מי אתה?"
ADMIN_PIN=1414       # קוד הגישה של המנהל (ברירת מחדל אם לא הוגדר)
```

בוחרים אותו ממסך "מי אתה?" — ולזהות מנהל (ולזהות מנהל **בלבד**) המערכת מבקשת את קוד הגישה. מיד לאחר מכן יש גישה למסך "ניהול": הוספת שגרירים נוספים (למנהל חדש צריך גם להגדיר לו קוד), שינוי שם/מחיקה של שגריר קיים, איפוס קוד גישה למנהל, ניהול קטגוריות, ו**ייבוא מרוכז** (לשונית "ניהול" ← "ייבוא"). שיוך/שינוי שיוך לשגריר נעשה מתוך לשונית "הכל" (למנהל יש שם גם בורר שיוך על כל כרטיס).

**חשוב לדעת**: לשגריר רגיל אין קוד בכלל — רק זהות מנהל מוגנת בקוד. מעבר לכך, כל מי שנכנס לאתר יכול לערוך/למחוק כל איש קשר (לא רק את שלו) ולהתחלף לכל זהות שגריר רגילה בלי קוד. זו בחירה מכוונת לפי הבקשה — מתאים לשימוש פנימי בין צוות מוכר, לא לחשיפה כאתר ציבורי-פתוח.

## מבנה הפרויקט

```
recruitment/
├── server/
│   ├── index.js      ← שרת Express
│   ├── api.js         ← כל נקודות ה-API (REST)
│   ├── auth.js         ← גיבוב קוד גישה למנהל (scrypt)
│   ├── statuses.js      ← רשימת 5 הסטטוסים הקבועה
│   └── db.js             ← חיבור PostgreSQL + מיגרציה + יצירת שגריר-מנהל ראשוני
├── db/schema.sql          ← מבנה הטבלאות
├── public/index.html       ← כל הלקוח (HTML+CSS+JS, ללא build step)
├── package.json
├── railway.json
└── .env.example
```

## הרצה מקומית

```bash
cd recruitment
npm install
cp .env.example .env
# ערכו את .env עם כתובת ה-PostgreSQL שלכם (ואופציונלית ADMIN_NAME/ADMIN_PIN)
npm run migrate
npm start           # http://localhost:3000
```

## פריסה ל-Railway

זהו תיקיית משנה (monorepo) בתוך ריפו קיים — כדי לפרוס אותה כשירות נפרד:

1. ב-Railway → **New Service** → **Deploy from GitHub repo** → בחרו את הריפו הזה.
2. בהגדרות השירות (Settings) → **Root Directory** → הזינו `recruitment`.
3. **New** → **Database** → **Add PostgreSQL** באותו פרויקט — `DATABASE_URL` יוגדר אוטומטית לשירות.
4. (אופציונלי) הוסיפו משתנה סביבה `ADMIN_NAME` לשירות **לפני** ה-deploy הראשון, כדי לקבוע מראש את שם השגריר-מנהל הראשון.
5. **Settings → Generate Domain** לקבלת כתובת ציבורית.

השרת מריץ מיגרציה אוטומטית באתחול (`migrate()` ב-startup) ויוצר שגריר-מנהל ראשוני אם עדיין אין שגרירים במסד.

## הערות אבטחה

- הזיהוי "מי אני" הוא הצהרה עצמית (כותרת `x-ambassador-id` שהלקוח שולח לפי מי שנבחר במסך "מי אתה?") — אין סשן/טוקן אמיתי. לזהות מנהל יש שכבת הגנה קלה בלבד: קוד גישה (מגובב עם scrypt) שנבדק **פעם אחת בבחירת הזהות**; מרגע שנבחרה, הבקשות מזהות לפי המזהה בלבד, בלי לשלוח את הקוד שוב.
- בפועל: מי שיודע את קוד המנהל יכול לפעול כמנהל (כולל הוספת/מחיקת שגרירים וייבוא מרוכז); כל שאר הפעולות (עריכה, מחיקה, סיווג של כל איש קשר) פתוחות לכל זהות שגריר, בלי קוד בכלל. מתאים לשימוש פנימי בין צוות מוכר — אל תשתפו את קוד המנהל או את כתובת האתר מעבר לצוות השגרירים.
