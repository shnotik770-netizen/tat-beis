# מערכת גיוס שגרירים — ערב שותפות, בית ספר חב"ד עפולה

אתר קליל למכשירים ניידים לניהול "ערב שותפות": רשימת אנשי קשר, שגרירים שאחראים על קבוצת אנשים, ומעקב סטטוסים לכל אחד. Node.js (Express) + PostgreSQL, מוכן לפריסה ב-Railway.

## מה יש במערכת

- **התחברות שגרירים** לפי שם + קוד אישי (בלי אימיילים/סיסמאות מסובכות).
- כל שגריר רואה **רק את הרשימה שלו**, ובנפרד את **מי עוד לא משויך לאף שגריר** (ואפשר "לקחת" אותם לרשימה האישית בלחיצה).
- כל שגריר יכול **להוסיף אנשי קשר חדשים** — משויכים אליו אוטומטית.
- **סיווג חופשי** לכל איש קשר (קהילה / הורה בית ספר / וכו') — קטגוריות נוצרות "תוך כדי" ומתעדכנות לבד.
- **5 סטטוסים קבועים**: שיחה ראשונית, בודק, מגיע לאירוע, לא יכול להגיע אבל רוצה לתרום, לא יכול להגיע לאירוע.
- **היסטוריה מלאה** לכל איש קשר — מה היה הסטטוס הראשוני, מה הקודם, מה הנוכחי, מתי ועל ידי מי.
- **מסך ניהול למנהל בלבד**: הוספת/עריכת שגרירים (כולל איפוס קוד כניסה), ניהול קטגוריות, טבלת כל אנשי הקשר עם שיוך/שינוי שיוך לשגריר, ו**ייבוא מרוכז** — הדבקת עשרות/מאות שורות בבת אחת מאקסל/Google Sheets.

## קוד גישה כמנהל

בהרצה הראשונה (כשעדיין אין אף שגריר במסד הנתונים) המערכת יוצרת אוטומטית משתמש מנהל, לפי משתני הסביבה:

```
ADMIN_NAME=מנהל     # שם ההתחברות
ADMIN_PIN=1234       # קוד הכניסה
```

**מומלץ להגדיר את אלה לפני הפריסה הראשונה** (ב-Railway: Variables), או להיכנס מיד לאחר העלייה עם הערכים המוגדרים כברירת מחדל ולשנות קוד. כמנהל אפשר: להוסיף שגרירים חדשים, לאפס קוד כניסה לכל שגריר, לנהל קטגוריות, לשייך/לשנות שיוך של כל איש קשר, ולייבא רשימות גדולות בבת אחת (לשונית "ניהול" ← "ייבוא").

## מבנה הפרויקט

```
recruitment/
├── server/
│   ├── index.js      ← שרת Express
│   ├── api.js         ← כל נקודות ה-API (REST)
│   ├── auth.js         ← גיבוב קוד כניסה + טוקן התחברות
│   ├── statuses.js      ← רשימת 5 הסטטוסים הקבועה
│   └── db.js             ← חיבור PostgreSQL + מיגרציה + יצירת מנהל ראשוני
├── db/schema.sql          ← מבנה הטבלאות
├── public/index.html       ← כל הלקוח (HTML+CSS+JS, ללא build step)
├── package.json
├── railway.json
└── .env.example
```

## הרצה מקומית

```bash
cd recruitment
npm install
cp .env.example .env
# ערכו את .env עם כתובת ה-PostgreSQL שלכם (ואופציונלית ADMIN_NAME/ADMIN_PIN)
npm run migrate
npm start           # http://localhost:3000
```

## פריסה ל-Railway

זהו תיקיית משנה (monorepo) בתוך ריפו קיים — כדי לפרוס אותה כשירות נפרד:

1. ב-Railway → **New Service** → **Deploy from GitHub repo** → בחרו את הריפו הזה.
2. בהגדרות השירות (Settings) → **Root Directory** → הזינו `recruitment`.
3. **New** → **Database** → **Add PostgreSQL** באותו פרויקט — `DATABASE_URL` יוגדר אוטומטית לשירות.
4. (אופציונלי אך מומלץ) הוסיפו משתני סביבה `ADMIN_NAME` ו-`ADMIN_PIN` לשירות **לפני** ה-deploy הראשון, כדי לקבוע מראש את פרטי המנהל.
5. **Settings → Generate Domain** לקבלת כתובת ציבורית.

השרת מריץ מיגרציה אוטומטית באתחול (`migrate()` ב-startup) ויוצר את המנהל הראשוני אם עדיין אין שגרירים במסד.

## הערות אבטחה

- קוד הכניסה (PIN) נשמר מגובב (scrypt + salt), לא כטקסט גלוי.
- ההתחברות מבוססת טוקן פשוט (session token) הנשמר בדפדפן — מספיק לשימוש פנימי בין שגרירים מוכרים, לא מיועד לחשיפה ציבורית רחבה.
- כל שגריר רגיל יכול לערוך/לעדכן סטטוס רק לאנשי קשר המשויכים אליו; פעולות ניהול (הוספת שגריר, שיוך מחדש, ייבוא מרוכז, מחיקת קטגוריה) מוגבלות למשתמש עם הרשאת מנהל.
