# מערכת גיוס שגרירים — ערב שותפות, בית ספר חב"ד עפולה

אתר קליל למכשירים ניידים לניהול "ערב שותפות": רשימת אנשי קשר, שגרירים שאחראים על קבוצת אנשים, ומעקב סטטוסים לכל אחד. Node.js (Express) + PostgreSQL, מוכן לפריסה ב-Railway.

## מה יש במערכת

- **אין מסך התחברות.** בכניסה לאתר בוחרים "מי אתה?" מרשימת השגרירים (שם בלבד, בלי סיסמה/קוד) — הבחירה נשמרת במכשיר. כל שגריר יכול לראות את כל שאר השגרירים ברשימה, ואפשר "להתחלף" ולפעול בשם כל שגריר אחר בכל רגע (כפתור "🔄 החלף זהות").
- 5 לשוניות רשימה: **שלי** (מי שמשויך אליי), **פתוחים** (מי שעוד לא משויך לאף שגריר — עם כפתור "קח לרשימה שלי"), **הכל** (כל הרשימה, פתוחה לצפייה ולסיווג לכולם — ולמנהל גם עם שיוך/שינוי שיוך לשגריר), **מועמדים** (ראו סעיף מועמדים לשגרירות למטה), ו**הוספה**.
- בכל לשונית רשימה יש **חיפוש** (שם/טלפון), **מיון** (החדשים ביותר / לפי שם / לפי סטטוס), סינון לפי קטגוריה וסטטוס, ותיבת "**להציג רק ללא סיווג**".
- כל שגריר יכול **להוסיף אנשי קשר חדשים** — משויכים אליו אוטומטית (אלא אם המנהל בוחר שיוך אחר).
- **סיווג מרובה וחופשי**: לכל איש קשר אפשר לצרף כמה סיווגים (קהילה / הורה בית ספר / וכו'), ולערוך/להוסיף/להסיר בכל רגע — פתוח לכל שגריר, לא רק לאחראי על אותו איש קשר. קטגוריות חדשות נוצרות "תוך כדי".
- **5 סטטוסים קבועים**: שיחה ראשונית, בודק, מגיע לאירוע, לא יכול להגיע אבל רוצה לתרום, לא יכול להגיע לאירוע. **היסטוריה מלאה** לכל איש קשר — מה היה הסטטוס הראשוני, מה הקודם, מה הנוכחי, מתי ועל ידי מי.
- **מועמדים לשגרירות**: כל שגריר שנתקל במישהו שלדעתו יתאים להיות שגריר בעצמו יכול לסמן אותו ככה מתוך כרטיס איש הקשר — ומיד לבחור: **"אני לוקח אחריות"** (משייך את המועמד אליי) או **"לשאול שגרירים אחרים"** (משאיר פתוח לכל מי שרוצה לקחת). מי שמשויך יכול גם לוותר על האחריות בחזרה לרשימה הפתוחה. לשונית "מועמדים" מרכזת את כל מי שסומן כך.
- **מחיקת אנשי קשר לא רלוונטיים** — כפתור מחיקה (עם אישור) בכל כרטיס וגם בתוך כרטיס הפרטים, פתוח לכל שגריר.
- **מסך ניהול למנהל בלבד**: הוספת/מחיקת שגרירים, ניהול קטגוריות, ו**ייבוא מרוכז** — הדבקת עשרות/מאות שורות (שם/טלפון/סיווגים) בבת אחת מאקסל/Google Sheets.

## מי הוא "מנהל"?

בהרצה הראשונה (כשעדיין אין אף שגריר במסד הנתונים) המערכת יוצרת אוטומטית שגריר-מנהל אחד, לפי משתנה הסביבה:

```
ADMIN_NAME=מנהל     # השם שיופיע ברשימת "מי אתה?"
```

בוחרים אותו ממסך "מי אתה?" ומיד יש גישה למסך "ניהול": הוספת שגרירים נוספים (אפשר לסמן מי מהם גם מנהל), ניהול קטגוריות, ו**ייבוא מרוכז** (לשונית "ניהול" ← "ייבוא") — מדביקים שורות בפורמט `שם [טאב] טלפון [טאב] סיווג/ים [טאב] שם שגריר (אופציונלי)` (אפשר כמה סיווגים באותה שורה, מופרדים בפסיק) וכל הרשימה נכנסת בבת אחת. שיוך/שינוי שיוך לשגריר לכל איש קשר נעשה מתוך לשונית "הכל" (זמינה גם למנהל, עם תוספת בורר השיוך על כל כרטיס).

**חשוב לדעת**: אין כאן הגנת סיסמה בכלל — כל מי שנכנס לאתר יכול לבחור כל זהות מהרשימה, כולל זהות מנהל, ולערוך/למחוק כל איש קשר (לא רק את שלו). זו בחירה מכוונת לפי הבקשה (בלי מסך כניסה, וכולם יכולים "להיכנס" בשם כל אחד ולתחזק יחד את הרשימה המשותפת) — מתאים לשימוש פנימי בין צוות מוכר, לא לחשיפה כאתר ציבורי-פתוח.

## מבנה הפרויקט

```
recruitment/
├── server/
│   ├── index.js      ← שרת Express
│   ├── api.js         ← כל נקודות ה-API (REST)
│   ├── statuses.js      ← רשימת 5 הסטטוסים הקבועה
│   └── db.js             ← חיבור PostgreSQL + מיגרציה + יצירת שגריר-מנהל ראשוני
├── db/schema.sql          ← מבנה הטבלאות
├── public/index.html       ← כל הלקוח (HTML+CSS+JS, ללא build step)
├── package.json
├── railway.json
└── .env.example
```

## הרצה מקומית

```bash
cd recruitment
npm install
cp .env.example .env
# ערכו את .env עם כתובת ה-PostgreSQL שלכם (ואופציונלית ADMIN_NAME/ADMIN_PIN)
npm run migrate
npm start           # http://localhost:3000
```

## פריסה ל-Railway

זהו תיקיית משנה (monorepo) בתוך ריפו קיים — כדי לפרוס אותה כשירות נפרד:

1. ב-Railway → **New Service** → **Deploy from GitHub repo** → בחרו את הריפו הזה.
2. בהגדרות השירות (Settings) → **Root Directory** → הזינו `recruitment`.
3. **New** → **Database** → **Add PostgreSQL** באותו פרויקט — `DATABASE_URL` יוגדר אוטומטית לשירות.
4. (אופציונלי) הוסיפו משתנה סביבה `ADMIN_NAME` לשירות **לפני** ה-deploy הראשון, כדי לקבוע מראש את שם השגריר-מנהל הראשון.
5. **Settings → Generate Domain** לקבלת כתובת ציבורית.

השרת מריץ מיגרציה אוטומטית באתחול (`migrate()` ב-startup) ויוצר שגריר-מנהל ראשוני אם עדיין אין שגרירים במסד.

## הערות אבטחה

- אין סיסמאות ואין הצפנה של זהות — הזיהוי "מי אני" הוא הצהרה עצמית בלבד (כותרת `x-ambassador-id` שהלקוח שולח לפי מי שנבחר במסך "מי אתה?"). זה נעשה בכוונה, לפי הבקשה שלא יהיה מסך כניסה ושכל שגריר יוכל "להיכנס" בשם כל שגריר אחר.
- בפועל זה אומר: **כל אחד שיש לו את כתובת האתר יכול לפעול כמנהל**, כולל הוספת/מחיקת שגרירים וייבוא מרוכז. מתאים לשימוש פנימי בין צוות מוכר בלבד — אל תשתפו את הכתובת מעבר לצוות השגרירים.
- הרשאת "עריכה רק של אנשי הקשר שלי" נשמרת ברמת השרת (workflow), אבל אינה הגנת אבטחה אמיתית — כל אחד יכול "להתחלף" לזהות אחרת בלחיצת כפתור ולערוך את הרשימה שלה.
