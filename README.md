# מערכת ניהול תשלומים — גרסת Node.js + PostgreSQL

זוהי המרה מלאה של המערכת מ-Google Apps Script + Google Sheets ל-**Node.js (Express) + PostgreSQL**, מוכנה לפריסה ב-**Railway** דרך **GitHub**.

## מבנה הפרויקט

```
├── server/
│   ├── index.js       ← שרת Express, מקבל בקשות API
│   ├── api.js          ← כל הפונקציות העסקיות (במקום Code.gs)
│   ├── logic.js        ← חישובי חוב/משפחה טהורים (הועברו כמעט מילה-במילה)
│   ├── db-access.js     ← שכבת גישה למסד הנתונים
│   └── db.js            ← חיבור PostgreSQL + הרצת סכמה
├── db/
│   └── schema.sql        ← מבנה הטבלאות
├── public/
│   └── index.html        ← הלקוח (HTML+CSS+JS) — כמעט זהה למקור
├── package.json
├── railway.json
└── .env.example
```

## איך זה עובד

**חשוב להבין:** לא נגעתי כמעט בכלל בקובץ ה-HTML/JS של הלקוח (`public/index.html`) — כל אלפי השורות של הממשק, הטפסים, החישובים בצד לקוח נשארו **בדיוק** כמו שהיו.

מה שכן שיניתי: בראש קובץ ה-`<script>`, הוספתי "שכבת תרגום" קטנה שמדמה את `google.script.run` (ה-API של Apps Script) אך במקום לתקשר עם Google Sheets, היא שולחת בקשות HTTP רגילות (`fetch`) לשרת ה-Express. כך כל הקוד שכתוב בסגנון:

```javascript
google.script.run
  .withSuccessHandler(fn)
  .withFailureHandler(errFn)
  .getAllData();
```

ממשיך לעבוד **בלי שינוי אחד**, רק שמאחורי הקלעים זה קורא ל-`POST /api/getAllData` בשרת שלכם.

בצד השרת, כל פונקציה שהייתה ב-`Code.gs` (כמו `getAllData`, `addStudent`, `addPayment` וכו') הועברה כמעט 1:1 ל-`server/api.js`, רק שבמקום לקרוא/לכתוב ל-Google Sheets היא קוראת/כותבת ל-PostgreSQL. **הלוגיקה העסקית עצמה — חישוב חוב, זיהוי משפחות לפי טלפון, מניעת כפילויות — לא השתנתה כלל.**

## הרצה מקומית (לבדיקה לפני פריסה)

דרוש: Node.js 18+‏, ו-PostgreSQL מותקן מקומית (או שירות ענן כמו Railway/Supabase).

```bash
npm install
cp .env.example .env
# ערכו את .env עם כתובת ה-PostgreSQL שלכם
npm run migrate     # יוצר את הטבלאות
npm start           # http://localhost:3000
```

## פריסה ל-Railway דרך GitHub

### שלב 1 — יצירת Repository ב-GitHub

```bash
git remote add origin https://github.com/<username>/<repo-name>.git
git branch -M main
git push -u origin main
```

(או: צרו repo ריק ב-GitHub קודם, דרך האתר, ואז הריצו את הפקודות למעלה)

### שלב 2 — יצירת פרויקט ב-Railway

1. היכנסו ל-[railway.app](https://railway.app) → **New Project**
2. בחרו **Deploy from GitHub repo** → בחרו את ה-repo שיצרתם
3. Railway יזהה אוטומטית שזה פרויקט Node.js ויתחיל בנייה

### שלב 3 — הוספת PostgreSQL

1. באותו פרויקט ב-Railway → **New** → **Database** → **Add PostgreSQL**
2. Railway יוצר אוטומטית משתנה סביבה `DATABASE_URL` ומחבר אותו לשירות שלכם — **אין צורך להגדיר את זה ידנית**

### שלב 4 — פריסה

Railway יפרוס אוטומטית בכל push ל-`main`. בפעם הראשונה, ודאו שהטבלאות נוצרו — זה קורה אוטומטית כשהשרת עולה (`migrate()` רץ ב-startup).

### שלב 5 — כתובת האתר

Railway ← Settings ← **Generate Domain** — תקבלו כתובת ציבורית (`https://your-app.up.railway.app`).

## ייבוא הנתונים הקיימים מ-Google Sheets

**אין צורך בסקריפט נפרד** — האפליקציה כבר כוללת פיצ'ר "ייבוא תלמידים" מובנה (הדבקת טקסט מופרד בטאבים). אחרי שהאתר עולה:

1. פתחו את הקובץ CSV/את הגיליון המקורי, **העתיקו את השורות** (ללא כותרות)
2. באתר: דף "תלמידים" → כפתור "📥 ייבוא" → הדביקו → ייבוא
3. אותו דבר עובד ל"דרישות" (כפתור "ייבוא מרשימה") ול"תשלומים ממתינים"

אם תרצו ייבוא ראשוני גדול יותר (מאות שורות בבת אחת) ישירות ל-DB בלי דרך הממשק — תגידו ואכין סקריפט ייבוא ישיר מ-CSV.

## הבדלים מהותיים מהגרסה המקורית

- **מזהי רשומות (IDs)**: אותו פורמט בדיוק (`S`/`C`/`D`/`P`/`N` + timestamp), כדי שלא יהיו התנגשויות אם תרצו לשלב נתונים מהמערכת הישנה
- **רשימות (תלמידים/סיווגים/דרישות)**: היו מחרוזת מופרדת בפסיקים בגיליון, עכשיו הן `TEXT[]` אמיתי ב-PostgreSQL — יעיל יותר ומאפשר שאילתות SQL ישירות בעתיד
- **סכומי תשלום לפי תלמיד**: היו JSON כמחרוזת, עכשיו `JSONB` אמיתי

## מה עוד לא הועבר / לבדוק

- לא הרצתי את זה מול מסד נתונים אמיתי (אין לי גישה ל-PostgreSQL בסביבה שבה אני עובד) — **חובה לבדוק את כל התרחישים המרכזיים** (הוספת תלמיד, תשלום, דרישה, כרטסת) אחרי הפריסה הראשונה
- אימות/הרשאות משתמשים — כרגע כל מי שיש לו את הכתובת יכול לגשת, בדיוק כמו הגרסה ב-Apps Script. אם צריך הגנה בסיסית (סיסמה), תגידו ונוסיף
